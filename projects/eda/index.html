    Reprodutibilidade

    O CSV bruto está versionado em data/hotel/hotel_bookings.csv (o mesmo arquivo do Kaggle e do TidyTuesday 2020-02-11). A semente 42 é usada em tudo o que sorteia. A partir da raiz do repositório:

    python docs/projects/eda/code/stage1_inspection.py
python docs/projects/eda/code/stage2_univariate.py
python docs/projects/eda/code/stage3_bivariate.py
python docs/projects/eda/code/pipeline.py
python docs/projects/eda/code/stage4_projections.py

    Os scripts imprimem todos os números desta página e regeram as 15 figuras (cerca de 70 s). Versões fixadas no requirements.txt. t-SNE e UMAP variam um pouco entre plataformas, por isso seus números aparecem arredondados. Nenhum modelo é treinado nesta entrega.

    O dataset reúne reservas de dois hotéis portugueses (julho de 2015 a agosto de 2017), e a pergunta é se uma reserva será cancelada. A ideia central da análise: o modelo só pode usar o que o hotel sabe no momento da reserva. Por isso descartamos as colunas que registram o desfecho e fazemos um split temporal (treinar no passado, testar no futuro).

    0. Proposal

    Escolhemos um dataset com uma pergunta de negócio concreta: cancelamentos obrigam o hotel a praticar overbooking e geram perda de receita. Ele também tem material para todos os itens do roteiro (ausentes, duplicatas, outliers, alta cardinalidade e vazamento) e está documentado num artigo revisado por pares.

    1. Initial inspection

    A — Data dictionary

    Fonte: sistema de gestão (PMS) de dois hotéis em Portugal, um resort no Algarve e um hotel urbano em Lisboa, anonimizado pelos autores do artigo. Cada linha é uma reserva com chegada entre 2015-07-01 e 2017-08-31. Não há ID de cliente nem de reserva. agent e company são códigos (IDs), não quantidades, e is_repeated_guest é um flag 0/1. Assumimos que adr está em euros (o artigo não informa a moeda).

    Duplicatas. 31.994 linhas (26,80%) são cópias exatas de outra. Sem ID de reserva, não dá para provar se são erros ou reservas iguais, mas os dados indicam reservas de grupo: a maioria das linhas copiadas é dos segmentos Groups e Offline TA/TO, e elas cancelam 58,4% (contra 26,2% das linhas sem cópia). Por isso as mantivemos: removê-las apagaria justamente as reservas de maior risco. O split temporal (1D) impede que cópias caiam dos dois lados.

    adults > 4 (máx. 55), adr negativo, adr = 5.400 16 + 1 + 1 mantidas; o recorte da seção 4A trata

    Vazamento. Estas cinco colunas saem em clean(), antes de qualquer estatística:

    Coluna descartada Evidência
    reservation_status É o alvo com outro nome: Check-Out ⇔ não cancelada (acurácia 100%).
    reservation_status_date Para canceladas, é a data do cancelamento: só existe depois do desfecho.
    assigned_room_type Quem teve o quarto trocado cancela 5,4% contra 41,6%: o quarto é atribuído sobretudo no check-in.
    required_car_parking_spaces Nenhuma das 7.416 reservas com vaga foi cancelada: o campo carrega o desfecho.
    arrival_date_year Não é vazamento, mas em produção o ano é sempre novo para o modelo. Serve só para montar a data do split.

    booking_changes: vazamento parcial

    Quem alterou a reserva cancela 15,7%, contra 40,9% de quem não alterou. O valor guardado é a contagem final (até o check-in ou o cancelamento), que o modelo não veria no momento da previsão. Mantivemos a coluna, mas a classificação deve medir o modelo com e sem ela.

    def clean(raw):
    """Row-level cleaning that uses no fitted statistic, so it is safe before the split.

    - builds ``arrival_date`` from the three date columns (needed for the temporal split);
    - fixes types: ``agent``/``company`` are codes, not quantities; NaN there means
      "no agent" / "no company" (the data article says so), so it becomes a level;
    - merges ``meal == "Undefined"`` into ``"SC"`` (the data article defines both as
      "no meal package") and the alpha-2 country code ``"CN"`` into ``"CHN"``;
    - removes bookings with zero guests (adults + children + babies == 0): a booking
      nobody would stay in is a recording error, not an observation;
    - drops the leakage and time-proxy columns listed above.
    """
    df = raw.copy()
    df["arrival_date"] = pd.to_datetime(
        df["arrival_date_year"].astype(str)
        + "-" + df["arrival_date_month"]
        + "-" + df["arrival_date_day_of_month"].astype(str),
        format="%Y-%B-%d",
    )
    for col in ("agent", "company"):
        df[col] = df[col].map(lambda v: "none" if pd.isna(v) else str(int(v)))
    df["meal"] = df["meal"].replace("Undefined", "SC")
    # One country is coded twice: "CN" (ISO alpha-2) next to "CHN" (alpha-3, like every other level).
    df["country"] = df["country"].replace("CN", "CHN")
    df["is_repeated_guest"] = df["is_repeated_guest"].astype(str)

    guests = df["adults"] + df["children"].fillna(0) + df["babies"]
    df = df.loc[guests > 0].copy()

    df = df.drop(columns=list(LEAKAGE) + list(TIME_PROXY))
    return df.reset_index(drop=True)

    Depois da limpeza: 119.210 linhas × 26 features (14 numéricas, 12 categóricas) mais o alvo.

    C — Target

    No conjunto limpo, 62,92% das reservas não foram canceladas e 37,08% foram (razão 1,70 : 1). No treino a taxa é 36,09% e no teste 40,99%. O desbalanceamento é moderado: não exige reamostragem, mas um modelo que sempre diz "não cancela" já acerta 63,91% do treino e 59,01% do teste. Por isso a acurácia sozinha não basta: a próxima entrega reporta precision e recall da classe cancelada.

    D — Train and test

    O split é temporal: as reservas são ordenadas pela data de chegada e os últimos 20% viram teste. O corte cai em 2017-04-22: treino com 95.192 linhas (79,85%) e teste com 24.018 (20,15%). Antes do split só rodam as regras fixas de clean(), que não calculam nenhuma estatística; tudo o que é ajustado (recortes, imputação, categorias, escala) usa só o treino, assim como as seções 2 a 4.

    TEST_SHARE = 0.20


def split(df):
    """Temporal split: the last 20% of arrivals (by date) are the test set.

    The cut falls on a whole day, so every booking with the same arrival date -- in
    particular the identical rows of a group booking -- lands on one side only. The seed
    is not used to split, but it is used, with the same value, by every sampling in the
    other scripts.
    """
    order = df.sort_values(["arrival_date"], kind="stable")
    cumulative = np.arange(1, len(order) + 1) / len(order)
    cut_date = order["arrival_date"].iloc[np.searchsorted(cumulative, 1 - TEST_SHARE)]
    test_mask = df["arrival_date"] >= cut_date
    train = df.loc[~test_mask].reset_index(drop=True)
    test = df.loc[test_mask].reset_index(drop=True)
    return train, test, cut_date


def load_split():
    """What every other script calls: cleaned train and test frames plus the cut date."""
    return split(clean(load_raw()))

    Por que temporal e não aleatório estratificado:

    1. É o uso real: o hotel prevê reservas futuras a partir do histórico.
    2. Duplicatas de grupo: com o corte em dia inteiro, nenhuma linha de teste tem cópia no treino; num split aleatório, 33,30% do teste teria, e o modelo pareceria melhor do que é.
    3. Níveis novos aparecem de verdade no teste (países, agências e empresas que o treino não tem), e o pré-processamento precisa lidar com isso.

    O preço é a deriva: o teste cancela 40,99% contra 36,09% no treino, e a população muda (por exemplo, a fatia de Portugal cai de 43,4% para 29,8%). Isso vai para a tabela de riscos.

    3. Bivariate and multivariate analysis

    A — Numerical × numerical

    Usamos Spearman e não Pearson porque as features são muito assimétricas, são quase todas contagens e têm valores extremos isolados (Tabela 3). Spearman usa postos, então um 5.400 em adr não distorce a correlação.

    Não há par redundante. O par mais correlacionado é lead_time × stays_in_week_nights, ρ = +0,287; nenhum par passa de |ρ| = 0,3, então todas as 14 numéricas ficam.

    Com o alvo, as mais associadas são lead_time (+0,337) e total_of_special_requests (−0,266). previous_cancellations (+0,317) também aparece forte, mas é o artefato da seção 1B.

    4. Preprocessing

    A — Strategies

    Cada estratégia é ajustada só no treino, dentro do pipeline da seção 4C, e vem de um achado anterior. O destino é uma rede neural, que precisa de entradas sem NaN, numéricas, em escala parecida e sem valores extremos dominando o gradiente.

    Tabela 7 — Estratégias de pré-processamento.

    # Problema Estratégia Achado que motiva
    1 Valores ausentes children: mediana do treino. country: nível unknown. agent/company: NaN vira o nível none ("sem agência/empresa"); imputar a moda apagaria essa informação. Tabela 2
    2 Outliers Recorte de cada numérica aos quantis 0,1% e 99,9% do treino; depois log1p em 7 features de cauda longa (lead_time, as duas de noites, as duas de histórico, booking_changes, days_in_waiting_list). adr fica sem log. Nenhuma linha é removida. Tabela 3 (assimetrias), Figuras 3 e 4
    3 Encoding (inclusive nível novo no teste) One-hot em tudo. Nas 3 de alta cardinalidade, níveis com menos de 100 linhas viram uma coluna infrequent, e todo nível novo do teste cai nela. Nas 9 de baixa, nível novo vira uma linha toda zero. Tabela 4, Figura 6, seção 1D
    4 Escala StandardScaler nas 14 numéricas, ajustado no treino; one-hot fica em 0/1. Tabela 3: escalas de 0–5 a 0–5.400

    Efeito do recorte: altera 695 linhas do treino (0,73%) e elimina a diária negativa, a diária de 5.400 e os 55 adultos sem perder linhas.

    Por que 100 linhas: com 100 reservas, a taxa de cancelamento de um nível já é estimada com erro de no máximo cerca de 5 pontos percentuais; abaixo disso o nível é ruído.

    B — Dimensionality reduction

    As três projeções usam a saída do pipeline (193 colunas), porque é isso que o modelo verá. A PCA é ajustada no treino inteiro; t-SNE e UMAP usam uma amostra de 5.000 linhas do treino (semente 42). Para comparar os desenhos com um número, usamos a pureza de vizinhança: a fração dos 10 vizinhos mais próximos de cada ponto que tem o mesmo rótulo. No espaço original de 193 dimensões ela é 0,728; um desenho aleatório daria cerca de 0,54.

    PCA. PC1 explica 10,81% e PC2 8,88%: juntas, 19,69%. São precisas 27 componentes para 90% (Figura 13): não há um eixo dominante, porque as numéricas são pouco correlacionadas e o one-hot espalha a variância em muitas direções. Loadings: PC1 é "tamanho e preço da reserva" (adr +0,42, adults +0,40); PC2 é "antecedência" (lead_time +0,57, days_in_waiting_list +0,33). Como lead_time é o sinal mais forte do alvo, as canceladas se concentram no alto do plano. Pureza: 0,645.

    t-SNE (perplexidade 5 e 50). Com 5 o desenho é uma nuvem única; com 50 aparecem ilhas compactas, quase todas canceladas. Os 10% de pontos mais altos do desenho de perplexidade 50 são 86,8% cancelados, na maioria Non Refund e Groups. Pureza ≈ 0,72 nas duas.

    UMAP (n_neighbors 5 e 50). Com 5 vizinhos o UMAP quebra a amostra em dezenas de pequenos satélites; com 50 junta quase tudo numa massa com algumas ilhas, duas delas só de canceladas. Pureza ≈ 0,72 e ≈ 0,71.

    Comparação. t-SNE e UMAP mostram ilhas de cancelamento que a PCA só mostra como uma mancha difusa. Mas a pureza deles (0,71–0,72) é igual à do espaço original (0,728): eles preservam a vizinhança que já existe, não criam separação nova. A PCA em 2D perde parte dela (0,645). Conclusões: (i) a estrutura dos dados não cabe em duas direções lineares; (ii) mesmo no espaço completo cerca de 27% dos vizinhos têm o rótulo oposto, um ruído que nenhum modelo elimina; (iii) se uma rede não linear vale a pena é pergunta para a próxima entrega, comparando a MLP com um modelo linear.

    class QuantileClipper(BaseEstimator, TransformerMixin):
    """Clip each column to the [lower, upper] quantiles learned on the training data."""

    def __init__(self, lower=0.001, upper=0.999):
        self.lower = lower
        self.upper = upper

    def fit(self, X, y=None):
        X = np.asarray(X, dtype=float)
        self.lower_ = np.nanquantile(X, self.lower, axis=0)
        self.upper_ = np.nanquantile(X, self.upper, axis=0)
        self.n_features_in_ = X.shape[1]
        return self

    def transform(self, X):
        return np.clip(np.asarray(X, dtype=float), self.lower_, self.upper_)

    def get_feature_names_out(self, input_features=None):
        return np.asarray(input_features, dtype=object)

    def numeric_branch(log):
    steps = [
        ("impute", SimpleImputer(strategy="median")),  # children: 4 NaN
        ("clip", QuantileClipper(*CLIP)),
    ]
    if log:
        steps.append(("log1p", FunctionTransformer(np.log1p, feature_names_out="one-to-one")))
    steps.append(("scale", StandardScaler()))
    return Pipeline(steps)


def build_preprocessor():
    """Unfitted preprocessor. Fit it on the training split only."""
    return ColumnTransformer(
        transformers=[
            ("num_log", numeric_branch(log=True), LOG_FEATURES),
            ("num_lin", numeric_branch(log=False), LINEAR_FEATURES),
            ("cat_low", Pipeline([
                ("impute", SimpleImputer(strategy="constant", fill_value="unknown")),
                ("onehot", OneHotEncoder(handle_unknown="ignore", sparse_output=False)),
            ]), CATEGORICAL_LOW),
            ("cat_high", Pipeline([
                ("impute", SimpleImputer(strategy="constant", fill_value="unknown")),  # country: 488 NaN
                ("onehot", OneHotEncoder(min_frequency=MIN_FREQUENCY,
                                         handle_unknown="infrequent_if_exist", sparse_output=False)),
            ]), CATEGORICAL_HIGH),
        ],
        verbose_feature_names_out=False,
    )


def fit_transform_splits(train, test):
    """Fit on train, transform both; returns (X_train, X_test, feature_names, preprocessor)."""
    pre = build_preprocessor()
    X_train = pre.fit_transform(train, train[TARGET])
    X_test = pre.transform(test)
    return X_train, X_test, pre.get_feature_names_out(), pre

    5. Synthesis

    Para quem vai construir o modelo:

    1. O alvo tem 36,1% de positivos no treino e 41,0% no teste (Figuras 1 e 2), e o teste é uma população diferente. Base mínima: responder sempre "não cancela" acerta 59,0% do teste. Reportar precision e recall da classe cancelada.
    2. As features mais informativas são conhecidas na reserva: deposit_type, agent, country, market_segment (Tabela 5) e, entre as numéricas, lead_time e total_of_special_requests (seção 3A). Não há par numérico redundante (Figura 7).
    3. O pré-processamento está pronto e é importável: 193 colunas, sem NaN, níveis novos tratados (tabela de checagens da seção 4C). Não refazer o split: usar data.load_split().
    4. Há ruído que nenhum modelo elimina: cerca de 27% dos vizinhos de cada reserva têm o rótulo oposto (seção 4B, Figuras 13–15). Comparar a MLP com um modelo linear.
    Risco Evidência Plano
    previous_cancellations é um artefato não bate com a definição e some no teste (seção 1B) treinar com e sem a coluna; a versão sem é a candidata a final
    booking_changes é contagem final 15,7% × 40,9% de cancelamento (seção 1B) reportar o modelo com e sem a coluna
    Deriva entre treino e teste 36,1% × 41,0%; menos Portugal no teste (seção 1D) validação temporal dentro do treino, não k-fold aleatório
    Non Refund quase determinístico cancela 99,2% (seção 3B) medir o modelo também dentro de No Deposit
    Duplicatas de grupo 26,8% de cópias (seção 1B) mantidas; o split temporal evita cópias dos dois lados
