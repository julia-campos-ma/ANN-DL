    O arquivo bruto é data/hotel/hotel_bookings.csv (16,9 MB, 119.390 linhas × 32 colunas), versionado no repositório: é o hotel_bookings.csv do Kaggle, byte a byte igual à cópia pública do TidyTuesday 2020-02-11, de onde um clone limpo pode baixá-lo sem login caso o arquivo falte. Nenhum modelo é treinado nesta entrega.

    O dataset reúne as reservas de dois hotéis portugueses entre julho de 2015 e agosto de 2017, e a pergunta é se uma reserva será cancelada. O fio condutor da análise é a fronteira entre o que o hotel sabe no momento da reserva e o que ele só sabe depois: quatro colunas do arquivo registram o desfecho (ou só mudam para quem de fato chegou) e precisam sair antes de qualquer estatística, uma quinta (previous_cancellations) se comporta como vazamento sem parecer, e o próprio split precisa respeitar o tempo, porque o uso real do modelo é prever o futuro a partir do passado.

    0. Proposal

    Como equipe de alunos de Administração, buscamos um dataset com uma pergunta de negócio concreta, em que o resultado do modelo se traduzisse diretamente numa decisão gerencial. Testamos alguns candidatos em análises exploratórias rápidas, feitas com apoio do Claude (ver ai_use), e este foi o mais adequado ao projeto por três motivos: (i) o problema é real e mensurável — cancelamentos obrigam o hotel a praticar overbooking e geram perda de receita; (ii) os dados dão material a todos os itens do roteiro — ausentes com significado, duplicatas, outliers, categorias de alta cardinalidade e uma história de vazamento clara; e (iii) cada variável está documentada num artigo revisado por pares, e o arquivo (16,9 MB) cabe no repositório. Foi o único dataset submetido na proposta.

    1. Initial inspection

    A — Data dictionary

    Fonte. Dois hotéis em Portugal, um resort no Algarve e um hotel urbano em Lisboa, extraídos do sistema de gestão (PMS) dos hotéis pelos autores do artigo e anonimizados. Cada linha é uma reserva (não um hóspede nem uma estadia) com chegada prevista entre 2015-07-01 e 2017-08-31, cancelada ou não. Não há identificador de cliente nem de reserva, então a mesma pessoa pode aparecer em várias linhas sem que isso seja detectável.

    A Tabela 1 segue o artigo; a coluna "no arquivo" diz como o pandas lê a coluna, e a última marca o que fizemos com ela. Três colunas numéricas no arquivo são códigos, não quantidades: agent e company são IDs de agência e empresa lidos como float64 (porque têm NaN), e is_repeated_guest é um flag 0/1. arrival_date_month é o nome do mês por extenso, em inglês. O artigo não informa a moeda de adr; sendo hotéis portugueses, assumimos euros.

    Ausentes. Só quatro colunas têm NaN, e os dois casos grandes não são aleatórios: o artigo define NaN em agent e company como "não houve agência/empresa", o que os dados confirmam.

    Vazamento. As cinco colunas da tabela abaixo são descartadas em clean(), antes de qualquer estatística. As duas primeiras são o desfecho; as duas seguintes se comportam como se só fossem preenchidas para quem chegou, e a última é um proxy do tempo.

    Coluna descartada Evidência
    reservation_status Check-Out ⇔ is_canceled = 0 (75.166 linhas) e Canceled/No-Show ⇔ is_canceled = 1 (43.017 + 1.207): acurácia 100%.

    required_car_parking_spaces 7.416 reservas pedem vaga e nenhuma delas foi cancelada (0,0%). Nossa hipótese é que o campo é registrado na chegada (ou zerado no cancelamento); de um jeito ou de outro, ele carrega o desfecho.
    arrival_date_year Não é vazamento, mas em produção o ano é sempre um valor que o modelo nunca viu; e, embora 17,4% do treino também seja de 2017, no teste o ano é constante. Serve só para montar arrival_date.

    booking_changes: vazamento parcial

    Quem alterou a reserva cancela 15,7% (18.076 linhas), contra 40,9% de quem não alterou. O artigo define a coluna como alterações "até o check-in ou o cancelamento", então o valor armazenado é a contagem final, que nenhum momento anterior de previsão enxerga, e uma reserva cancelada tem menos tempo para acumular alterações. Mantivemos a coluna porque alterações feitas até a data da previsão são informação legítima, mas ela entra na tabela de riscos da seção 5 com um plano: a entrega de classificação deve medir o modelo com e sem ela.

    def clean(raw):
    """Row-level cleaning that uses no fitted statistic, so it is safe before the split.

    - builds ``arrival_date`` from the three date columns (needed for the temporal split);
    - fixes types: ``agent``/``company`` are codes, not quantities; NaN there means
      "no agent" / "no company" (the data article says so), so it becomes a level;
    - merges ``meal == "Undefined"`` into ``"SC"`` (the data article defines both as
      "no meal package") and the alpha-2 country code ``"CN"`` into ``"CHN"``;
    - removes bookings with zero guests (adults + children + babies == 0): a booking
      nobody would stay in is a recording error, not an observation;
    - drops the leakage and time-proxy columns listed above.
    """
    df = raw.copy()
    df["arrival_date"] = pd.to_datetime(
        df["arrival_date_year"].astype(str)
        + "-" + df["arrival_date_month"]
        + "-" + df["arrival_date_day_of_month"].astype(str),
        format="%Y-%B-%d",
    )
    for col in ("agent", "company"):
        df[col] = df[col].map(lambda v: "none" if pd.isna(v) else str(int(v)))
    df["meal"] = df["meal"].replace("Undefined", "SC")
    # One country is coded twice: "CN" (ISO alpha-2) next to "CHN" (alpha-3, like every other level).
    df["country"] = df["country"].replace("CN", "CHN")
    df["is_repeated_guest"] = df["is_repeated_guest"].astype(str)

    guests = df["adults"] + df["children"].fillna(0) + df["babies"]
    df = df.loc[guests > 0].copy()

    df = df.drop(columns=list(LEAKAGE) + list(TIME_PROXY))
    return df.reset_index(drop=True)

    Depois da limpeza: 119.210 linhas × 26 features (14 numéricas, 12 categóricas), mais o alvo e a arrival_date usada só no split.

    C — Target

    No conjunto limpo, 75.011 reservas não canceladas (62,92%) e 44.199 canceladas (37,08%): razão maior/menor de 1,70 (no arquivo bruto a taxa é 37,0%). No treino (seção 1D) a proporção é 63,91% / 36,09%, razão 1,77; no teste, 59,01% / 40,99%. Um classificador que sempre responde "não cancela" acerta 63,91% do treino e 59,01% do teste, e é essa a régua mínima da próxima entrega: acurácia só interessa acima disso, e, com um terço de positivos, recall e precision da classe cancelada contam mais que a acurácia.

    D — Train and test

    O split é temporal, em data.split: as reservas são ordenadas pela data de chegada e os últimos 20% viram teste. O corte cai em 2017-04-22, em dia inteiro: treino com 95.192 linhas (79,85%, chegadas de 2015-07-01 a 2017-04-21) e teste com 24.018 (20,15%, de 2017-04-22 a 2017-08-31). Antes dele só rodam as regras fixas de clean() (remover reservas sem hóspede, fundir dois códigos do mesmo nível, descartar colunas), que não usam estatística nenhuma; toda estatística ajustada (quantis de recorte, mediana de imputação, categorias conhecidas, média e desvio da escala) é calculada só no treino, e as seções 2 a 4 usam só o treino.

    TEST_SHARE = 0.20


def split(df):
    """Temporal split: the last 20% of arrivals (by date) are the test set.

    The cut falls on a whole day, so every booking with the same arrival date -- in
    particular the identical rows of a group booking -- lands on one side only. The seed
    is not used to split, but it is used, with the same value, by every sampling in the
    other scripts.
    """
    order = df.sort_values(["arrival_date"], kind="stable")
    cumulative = np.arange(1, len(order) + 1) / len(order)
    cut_date = order["arrival_date"].iloc[np.searchsorted(cumulative, 1 - TEST_SHARE)]
    test_mask = df["arrival_date"] >= cut_date
    train = df.loc[~test_mask].reset_index(drop=True)
    test = df.loc[test_mask].reset_index(drop=True)
    return train, test, cut_date


def load_split():
    """What every other script calls: cleaned train and test frames plus the cut date."""
    return split(clean(load_raw()))

    Três razões para temporal em vez de aleatório-estratificado:

    1. É o uso real. O hotel quer prever cancelamentos de reservas futuras com o histórico; um split aleatório avaliaria o modelo em reservas contemporâneas às de treino.
    2. Entidades repetidas. Não há ID de cliente nem de reserva, mas cada data de chegada reúne em média 150 reservas, e as cópias de uma reserva de grupo compartilham a data. Com o corte em dia inteiro, nenhuma linha de teste tem cópia idêntica (nas 26 features e no alvo) no treino; num split aleatório estratificado com a mesma semente, 7.940 linhas de teste (33,30%) teriam. Um modelo que decorasse o treino pareceria ótimo sem ser.

    B — Dimensionality reduction

    As três projeções usam a saída do pipeline (193 colunas: 14 numéricas padronizadas e 179 de one-hot) para o treino, porque é isso que o modelo verá. A PCA é ajustada nas 95.192 linhas; t-SNE e UMAP, e os desenhos das três, usam a mesma amostra de 5.000 linhas de treino sorteada com a semente 42 (36,0% canceladas; 15,5% dos pontos têm uma cópia exata na amostra). Para comparar as projeções com um número e não só com o olho, o script calcula a pureza de vizinhança: a fração dos 10 vizinhos mais próximos de cada ponto que tem o mesmo rótulo. É uma estatística descritiva do desenho, não um modelo. Duas referências: uma arrumação aleatória dá 0,539 para essa proporção de classes, e a pureza medida no próprio espaço de 193 dimensões, antes de qualquer projeção, é 0,728.

    PCA. PC1 explica 10,81% e PC2 8,88%: juntas, 19,69% da variância; são necessárias 8 componentes para 50%, 16 para 80% e 27 para 90% (Figura 13, esquerda). Isso tem duas causas: as 14 numéricas padronizadas carregam a maior parte da variância total e são pouco correlacionadas entre si (|ρ| máximo 0,29, Figura 7), então não há um eixo dominante; e as 179 colunas de one-hot repartem o resto em muitas direções pequenas (dentro de cada feature elas são exatamente dependentes, pois somam 1). Chegar a 90% com 27 de 193 componentes mostra que a matriz comprime bem, mas não em duas dimensões. Os loadings são legíveis: PC1 é um eixo de "tamanho e preço da reserva" (adr +0,42, adults +0,40, stays_in_week_nights +0,31, total_of_special_requests +0,30, stays_in_weekend_nights +0,29, e previous_bookings_not_canceled −0,29 no sentido oposto); PC2 é um eixo de "antecedência" (lead_time +0,57, days_in_waiting_list +0,33, previous_cancellations +0,29, stays_in_week_nights +0,24, contra total_of_special_requests −0,30 e previous_bookings_not_canceled −0,21). PC2 alinha-se com os sinais da seção 3A, e por isso as canceladas se concentram na parte de cima do plano. Pureza no plano: 0,645.

    t-SNE (perplexidade 5 e 50, init="pca"). Com perplexidade 5 o desenho é uma nuvem com grumos pequenos e uma faixa laranja no alto; com 50 aparecem ilhas compactas. O script descreve os 10% de pontos mais acima do desenho de perplexidade 50: 86,8% cancelados, 78% Non Refund, 66% Groups, 90% City Hotel, lead_time mediano 270 dias, e 66% deles são cópias exatas de outro ponto.     UMAP (n_neighbors 5 e 50, min_dist=0.1).     class QuantileClipper(BaseEstimator, TransformerMixin):
    """Clip each column to the [lower, upper] quantiles learned on the training data."""

    def __init__(self, lower=0.001, upper=0.999):
        self.lower = lower
        self.upper = upper

    def fit(self, X, y=None):
        X = np.asarray(X, dtype=float)
        self.lower_ = np.nanquantile(X, self.lower, axis=0)
        self.upper_ = np.nanquantile(X, self.upper, axis=0)
        self.n_features_in_ = X.shape[1]
        return self

    def transform(self, X):
        return np.clip(np.asarray(X, dtype=float), self.lower_, self.upper_)

    def get_feature_names_out(self, input_features=None):
        return np.asarray(input_features, dtype=object)

    def numeric_branch(log):
    steps = [

            ("num_log", numeric_branch(log=True), LOG_FEATURES),
            ("num_lin", numeric_branch(log=False), LINEAR_FEATURES),
            ("cat_low", Pipeline([
                ("impute", SimpleImputer(strategy="constant", fill_value="unknown")),
                ("onehot", OneHotEncoder(handle_unknown="ignore", sparse_output=False)),
            ]), CATEGORICAL_LOW),
            ("cat_high", Pipeline([
                ("impute", SimpleImputer(strategy="constant", fill_value="unknown")),  # country: 488 NaN
                ("onehot", OneHotEncoder(min_frequency=MIN_FREQUENCY,
                                         handle_unknown="infrequent_if_exist", sparse_output=False)),
            ]), CATEGORICAL_HIGH),
        ],
        verbose_feature_names_out=False,
    )


def fit_transform_splits(train, test):
    """Fit on train, transform both; returns (X_train, X_test, feature_names, preprocessor)."""
    pre = build_preprocessor()
    X_train = pre.fit_transform(train, train[TARGET])
    X_test = pre.transform(test)
    return X_train, X_test, pre.get_feature_names_out(), pre

    5. Synthesis

    Para quem vai construir o modelo:

    1. O alvo tem 36,1% de positivos no treino e 41,0% no teste (Figura 1, Figura 2), e o teste é uma população diferente (menos Portugal, menos Non Refund, quase nenhum previous_cancellations > 0). Régua mínima: 63,9% de acurácia no treino e 59,0% no teste respondendo sempre "não cancela". Reporte recall e precision da classe cancelada e as curvas ROC e PR.
    2. As features mais informativas são conhecidas na reserva: deposit_type (V = 0,51), agent (0,41), country (0,37), market_segment (0,28) e, entre as numéricas, lead_time (ρ = +0,34) e total_of_special_requests (−0,27) (Tabela 5, Figuras 9–11). previous_cancellations (+0,32 no treino) não entra nessa lista: é o artefato do item 1B. Não há par numérico redundante (Figura 7).
    3. Non Refund cancela 99,2% (Figura 9) e Portugal 55,5% (Figura 10), e os dois estão ligados: um modelo pode ir longe só com isso. Avalie também o desempenho dentro de No Deposit, onde estão 87% das reservas e o problema real.
    4. O pré-processamento está pronto e é importável: 193 colunas, sem NaN, com níveis novos tratados (seção 4C). Não refaça o split: use data.load_split().
    5. Cerca de 27% dos vizinhos de cada reserva têm o rótulo oposto no espaço completo (seção 4B): há um teto de ruído, e as ilhas puras são blocos de grupo que qualquer modelo acerta. Compare a MLP com um modelo linear antes de atribuir ganho à não linearidade.
