    2. Perceptron

    Enunciado

    Exercises → Perceptron

    Visão geral

    O exercício usa um único perceptron de camada única , escrito à mão com NumPy, em dois cenários: dados linearmente separáveis (Exercise 1) e dados sobrepostos (Exercise 2). A mesma classe Perceptron, em code/perceptron.py, serve aos dois exercícios sem nenhuma alteração — o que muda é apenas o dado. O Exercise 2 acrescenta o algoritmo do bolso, que já está dentro da mesma classe: ele só "aparece" quando o treino não converge.

    Todo o código usa só numpy e matplotlib; nenhum modelo pronto do scikit-learn. A semente é np.random.default_rng(42), criada uma vez no topo de cada script.

    Desafios encontrados.

    • Quando avaliar o bolso. Avaliar a acurácia só ao fim de cada época dava um bolso de apenas 52,35%; como os pesos só mudam quando há uma atualização, o bolso passou a ser reavaliado logo após cada atualização (é o que o enunciado pede: copiar \((w, b)\) sempre que a acurácia no dataset completo superar todas as anteriores), e a curva da Figura 6 é registrada por época.
    • Como fazer o "η só reescala" valer. A prova do item D.3 exige partida em \(w = 0\), mas o enunciado manda inicializar \(w\) com \(\mathcal{N}(0, 0.01)\). Por isso a classe tem o parâmetro init_std (padrão 0.01), usado com 0 apenas para verificar D.3.
    • Ordem das amostras. O treino percorre as amostras sempre na mesma ordem (classe 0, depois classe 1), sem embaralhar. Isso é necessário para a comparação entre taxas de aprendizado do D.3 e tem efeito visível na análise do Exercise 2.

    Exercise 1

    A — Geração dos dados

    Duas classes 2D, 1000 pontos cada, amostradas com rng.multivariate_normal: classe 0 com média \([1.5, 1.5]\) e classe 1 com média \([5, 5]\), ambas com covariância \(\begin{bmatrix} 0.5 & 0 \\ 0 & 0.5 \end{bmatrix}\) (variância 0,5 em cada eixo, eixos independentes). A função generate_two_classes devolve X com shape (2000, 2) e y com rótulos \(\{0, 1\}\), classe 0 primeiro.

    B — Implementação do perceptron

    Modelo. Com \(\hat{y} = \text{step}(\mathbf{w}^\top \mathbf{x} + b)\), sendo \(\text{step}(z) = 1\) se \(z \ge 0\) e \(0\) caso contrário, e rótulos \(y, \hat{y} \in \{0, 1\}\), a regra de atualização, aplicada amostra a amostra, é

    \[ \mathbf{w} \leftarrow \mathbf{w} + \eta\,(y - \hat{y})\,\mathbf{x}, \qquad b \leftarrow b + \eta\,(y - \hat{y}). \]

    O termo de erro \(y - \hat{y}\) vale \(0\) quando o perceptron acerta (nada muda), \(+1\) quando previu 0 e o certo era 1 (empurra \(\mathbf{w}\) para \(\mathbf{x}\)) e \(-1\) no caso oposto (empurra \(\mathbf{w}\) para longe de \(\mathbf{x}\)). Inicialização: \(\mathbf{w} \sim \mathcal{N}(0, 0.01^2)\) e \(b = 0\); \(\eta = 0.01\). O treino para quando uma época inteira termina sem nenhuma atualização, ou ao completar 100 épocas; a acurácia no conjunto completo é registrada ao fim de cada época.

    """Perceptron de camada única, escrito à mão (só NumPy).

Este módulo é usado sem nenhuma alteração pelos Exercises 1 e 2 do enunciado:
a regra de atualização e o laço de treino são os mesmos; o que muda entre os
exercícios é apenas o dado. Ele contém:

    * ``generate_two_classes`` — geração das duas classes gaussianas 2D;
    * ``step``                 — ativação degrau;
    * ``decision_line``        — reta w·x + b = 0 para desenhar a fronteira;
    * ``Perceptron``           — predição, regra de atualização, laço de treino e
                                 rastreamento do "bolso" (pocket).
"""

import numpy as np

# Paleta usada em todas as figuras do exercício: só tons de rosa, azul e laranja.
NAVY = "#173F5F"        # azul escuro — classe 0
PINK = "#D6336C"        # rosa — classe 1
LIGHT_BLUE = "#4DABF7"  # azul claro — segunda linha/curva
ORANGE = "#E8590C"      # laranja — erros, fronteiras e destaques


def generate_two_classes(mean0, mean1, var, n_per_class, rng):
    """Gera duas classes 2D a partir de normais multivariadas de covariância ``var * I``.

    Retorna X com shape (2 * n_per_class, 2) e y com rótulos {0, 1}. As amostras da
    classe 0 vêm primeiro e as da classe 1 depois — a ordem é mantida no treino.
    """
    cov = np.array([[var, 0.0], [0.0, var]])  # covariância diagonal: eixos independentes
    X0 = rng.multivariate_normal(mean0, cov, size=n_per_class)
    X1 = rng.multivariate_normal(mean1, cov, size=n_per_class)
    X = np.vstack([X0, X1])
    y = np.concatenate([np.zeros(n_per_class, dtype=int), np.ones(n_per_class, dtype=int)])
    return X, y


def step(z):
    """Degrau: 1 se z >= 0, senão 0 (funciona para escalar ou array)."""
    return (z >= 0).astype(int)


def decision_line(w, b, x1):
    """Pontos (x1, x2) da fronteira w·x + b = 0, isolando x2 = -(w1·x1 + b) / w2.
    -> usada só pra desenhar a fronteira"""
    return -(w[0] * x1 + b) / w[1]


class Perceptron:
    """Perceptron com ativação degrau e rótulos y ∈ {0, 1}.

    Parâmetros
    ----------
    lr : taxa de aprendizado η.
    max_epochs : número máximo de épocas (uma época = uma passada por todas as amostras).
    rng : gerador NumPy usado só na inicialização de w.
    init_std : desvio-padrão da inicialização de w (padrão 0.01, como no enunciado).
        Só é alterado para 0 na verificação algébrica do item D.3 (partida em w = 0).
    """

    def __init__(self, lr=0.01, max_epochs=100, rng=None, init_std=0.01):
        self.lr = lr
        self.max_epochs = max_epochs
        self.init_std = init_std
        self.rng = rng if rng is not None else np.random.default_rng(42)

    # ---------------------------------------------------------------- predição
    def predict(self, X, w=None, b=None):
        """ŷ = step(w·x + b). Por padrão usa os pesos atuais; w e b podem ser passados
        explicitamente para avaliar outros pesos (ex.: os do bolso)."""
        w = self.w if w is None else w
        b = self.b if b is None else b
        return step(X @ w + b)

    def accuracy(self, X, y, w=None, b=None):
        """Fração de amostras classificadas corretamente."""
        return float(np.mean(self.predict(X, w, b) == y))

    # ------------------------------------------------------------------ treino
    def fit(self, X, y):
        """Treina com atualização online (amostra a amostra), sempre na mesma ordem.

        Regra de atualização (erro ∈ {0, +1, -1}):
            w ← w + η (y − ŷ) x
            b ← b + η (y − ŷ)

        Parada: uma época inteira sem nenhuma atualização (convergência) ou
        ``max_epochs`` épocas.

        Guarda também o "bolso" (pocket): o melhor (w, b) já visto, medido pela
        acurácia no conjunto completo. Como (w, b) só muda quando há uma atualização,
        a acurácia é reavaliada logo após CADA atualização — e o bolso só é substituído
        se a acurácia for estritamente maior que a do bolso atual. Em dados separáveis
        o bolso acaba com a mesma acurácia dos pesos finais; ele só importa quando não
        há convergência.
        """
        # Inicialização não nula: w ~ N(0, 0.01²), b = 0
        self.w = self.rng.normal(0.0, self.init_std, size=X.shape[1])
        self.b = 0.0

        self.acc_history = []        # acurácia dos pesos ATUAIS ao fim de cada época
        self.best_acc_history = []   # melhor acurácia até a época (curva do bolso)
        self.updates_history = []    # nº de atualizações (erros) em cada época
        self.w_history = [self.w.copy()]  # w antes do treino e após cada época
        self.b_history = [self.b]

        self.pocket_w, self.pocket_b = self.w.copy(), self.b
        self.pocket_acc = self.accuracy(X, y)   # começa pelo chute inicial
        self.pocket_epoch = 0                   # época em que o bolso foi salvo (0 = pesos iniciais)
        self.pocket_update = 0                  # nº da atualização em que o bolso foi salvo
        n_total_updates = 0
        self.converged = False
        self.epochs_run = 0
        self.total_updates = 0

        for epoch in range(1, self.max_epochs + 1):
            n_updates = 0
            for xi, yi in zip(X, y):
                y_hat = int(step(xi @ self.w + self.b))
                err = yi - y_hat            # 0 se acertou; ±1 se errou
                if err != 0:
                    self.w = self.w + self.lr * err * xi
                    self.b = self.b + self.lr * err
                    n_updates += 1
                    n_total_updates += 1

                    # Bolso: (w, b) acabou de mudar, então reavalia no dataset inteiro.
                    # ">" estrito: empates não substituem o bolso.
                    acc_now = self.accuracy(X, y)
                    if acc_now > self.pocket_acc:
                        self.pocket_w, self.pocket_b = self.w.copy(), self.b
                        self.pocket_acc = acc_now
                        self.pocket_epoch = epoch
                        self.pocket_update = n_total_updates

            acc = self.accuracy(X, y)
            self.acc_history.append(acc)
            self.updates_history.append(n_updates)
            self.w_history.append(self.w.copy())
            self.b_history.append(self.b)
            self.epochs_run = epoch

            self.best_acc_history.append(self.pocket_acc)  # curva do bolso ao fim da época

            if n_updates == 0:              # passada limpa: convergiu
                self.converged = True
                break
        self.total_updates = n_total_updates
        return self
    Passo a passo do código
    1. generate_two_classes monta a matriz de covariância \(0.5\,I\) e chama rng.multivariate_normal uma vez por classe. np.vstack empilha as duas nuvens em X e np.concatenate cria os rótulos (mil zeros e mil uns).
    2. step implementa o degrau com z >= 0, o que dá um array de booleanos; o .astype(int) converte para 0/1. Note o >=: em \(z = 0\) exato a previsão é 1.
    3. predict calcula X @ w + b para todas as amostras de uma vez (produto matriz-vetor) e aplica o degrau. Os argumentos opcionais w e b permitem avaliar outros pesos — é assim que os pesos do bolso são avaliados no Exercise 2.
    4. fit, inicialização. w recebe 2 valores de \(\mathcal{N}(0, 0.01)\) e b começa em 0. Em seguida são criadas as listas de histórico (acurácia por época, melhor acurácia por época, atualizações por época) e o bolso começa com os pesos iniciais.
    5. fit, laço interno. Para cada amostra (xi, yi): prevê y_hat, calcula err = yi - y_hat e, só se err != 0, aplica a regra de atualização. Isso é o aprendizado guiado por erro: acertos não mexem em nada.
    6. fit, bolso. Toda vez que há atualização, (w, b) mudou; reavalia-se a acurácia no dataset completo e, se for estritamente maior que a do bolso, copia-se (w, b) (.copy() é essencial, senão o bolso seria uma referência que muda junto com w).
    7. fit, fim da época. Guarda-se a acurácia atual, o número de atualizações e a melhor acurácia até ali. Se n_updates == 0, o perceptron acertou tudo numa passada completa sem mudar nenhum peso: convergiu, e o laço termina (break).
    8. decision_line isola \(x_2\) em \(w_1 x_1 + w_2 x_2 + b = 0\), dando \(x_2 = -(w_1 x_1 + b)/w_2\), para desenhar a fronteira.

    """Exercise 1 — Perceptron em dados linearmente separáveis.

Gera as duas classes do item A (Figura 1), treina o perceptron com η = 0.01
(itens B e C, Figuras 2 e 3), repete o treino com η = 1.0 (item D.2) e verifica
numericamente o resultado algébrico do item D.3 (η só reescala os pesos).

Uso (a partir da raiz do repositório):

    python docs/exercises/perceptron/code/exercise1_separable.py
"""

from pathlib import Path

import matplotlib.pyplot as plt
import numpy as np

from perceptron import (
    LIGHT_BLUE,
    NAVY,
    ORANGE,
    PINK,
    Perceptron,
    decision_line,
    generate_two_classes,
)

FIGURES = Path(__file__).resolve().parents[1] / "figures"
RNG = np.random.default_rng(42)  # (1)!

MEAN0, MEAN1, VAR, N_PER_CLASS = [1.5, 1.5], [5.0, 5.0], 0.5, 1000
COLORS = {0: NAVY, 1: PINK}  # paleta: só tons de rosa, azul e laranja


def scatter_classes(ax, X, y):
    """Dispersão das duas classes (classe 0 azul-escuro, classe 1 rosa)."""
    for cls in (0, 1):
        m = y == cls
        ax.scatter(X[m, 0], X[m, 1], s=12, alpha=0.5, color=COLORS[cls], label=f"Classe {cls}")
    ax.set_xlabel("$x_1$")
    ax.set_ylabel("$x_2$")


def plot_figure1(X, y):
    fig, ax = plt.subplots(figsize=(7, 6))
    scatter_classes(ax, X, y)
    ax.set_title("Figura 1 — Dados separáveis: 1000 pontos por classe")
    ax.legend()
    return fig


def plot_figure2(X, y, p, p_big):
    """Fronteira w·x + b = 0 (η = 0.01) sobre os dados; erros marcados com X vermelho."""
    fig, ax = plt.subplots(figsize=(7, 6))
    scatter_classes(ax, X, y)
    wrong = p.predict(X) != y  # (2)!
    ax.scatter(X[wrong, 0], X[wrong, 1], marker="x", s=60, color=ORANGE,
               label=f"Erros ({wrong.sum()})")
    x1 = np.array([X[:, 0].min() - 0.5, X[:, 0].max() + 0.5])
    ax.plot(x1, decision_line(p.w, p.b, x1), color=ORANGE, lw=2, label="Fronteira (η = 0.01)")
    ax.plot(x1, decision_line(p_big.w, p_big.b, x1), color=LIGHT_BLUE, ls="--", lw=1.8,
            label="Fronteira (η = 1.0)")
    ax.set_ylim(X[:, 1].min() - 0.5, X[:, 1].max() + 0.5)
    ax.set_title("Figura 2 — Fronteira de decisão do perceptron (dados separáveis)")
    ax.legend(loc="lower right")
    return fig


def plot_figure3(p):
    epochs = np.arange(1, len(p.acc_history) + 1)
    fig, ax = plt.subplots(figsize=(7, 4.5))
    ax.plot(epochs, p.acc_history, marker="o", color=NAVY, label="Acurácia (η = 0.01)")
    ax.set_xlabel("Época")
    ax.set_ylabel("Acurácia no conjunto completo")
    ax.set_ylim(0.0, 1.05)  # eixo completo: as primeiras épocas oscilam muito
    ax.set_title("Figura 3 — Acurácia por época (dados separáveis)")
    ax.legend(loc="center right")
    return fig


def main() -> None:
    FIGURES.mkdir(parents=True, exist_ok=True)

    # --- Item A: dados -----------------------------------------------------
    X, y = generate_two_classes(MEAN0, MEAN1, VAR, N_PER_CLASS, RNG)
    print(f"X: {X.shape}, y: {y.shape}, por classe: {np.bincount(y)}")
    fig1 = plot_figure1(X, y)
    fig1.savefig(FIGURES / "fig01-separable-data.png", dpi=150, bbox_inches="tight")
    plt.close(fig1)  # (3)!

    # --- Itens B e C: treino com η = 0.01 (o mesmo RNG segue o fluxo dos dados) ---
    p = Perceptron(lr=0.01, max_epochs=100, rng=RNG).fit(X, y)
    print("\n== η = 0.01 ==")
    print(f"w final = {p.w}, b final = {p.b:.4f}")
    print(f"épocas executadas = {p.epochs_run} (convergiu: {p.converged})")
    print(f"acurácia final = {p.accuracy(X, y):.4f}")
    print(f"atualizações por época: {p.updates_history}")
    print(f"w/||w|| = {p.w / np.linalg.norm(p.w)}")
    print(f"total de atualizações (erros corrigidos) = {p.total_updates}")

    # --- Item D.2: η = 1.0, mesma semente (novo RNG => mesma inicialização de w) ---
    rng2 = np.random.default_rng(42)
    X2, y2 = generate_two_classes(MEAN0, MEAN1, VAR, N_PER_CLASS, rng2)  # dados idênticos
    p_big = Perceptron(lr=1.0, max_epochs=100, rng=rng2).fit(X2, y2)
    print("\n== η = 1.0 ==")
    print(f"w final = {p_big.w}, b final = {p_big.b:.4f}")
    print(f"épocas executadas = {p_big.epochs_run} (convergiu: {p_big.converged})")
    print(f"acurácia final = {p_big.accuracy(X, y):.4f}")
    print(f"atualizações por época: {p_big.updates_history}")
    print(f"total de atualizações = {p_big.total_updates}")
    print(f"w/||w|| = {p_big.w / np.linalg.norm(p_big.w)}")
    u, v = p.w / np.linalg.norm(p.w), p_big.w / np.linalg.norm(p_big.w)
    cos = float(u @ v)
    print(f"cos(ângulo entre w/||w||) = {cos:.6f}  -> {np.degrees(np.arccos(min(cos, 1))):.3f}°")

    # --- Figuras 2 e 3 -----------------------------------------------------
    fig2 = plot_figure2(X, y, p, p_big)
    fig2.savefig(FIGURES / "fig02-decision-boundary.png", dpi=150, bbox_inches="tight")
    plt.close(fig2)
    fig3 = plot_figure3(p)
    fig3.savefig(FIGURES / "fig03-accuracy-epochs.png", dpi=150, bbox_inches="tight")
    plt.close(fig3)

    # --- Item D.3: verificação numérica partindo de w = 0, b = 0 ------------
    print("\n== D.3: partida em w = 0, b = 0 ==")
    runs = {}
    for lr in (0.01, 1.0):
        q = Perceptron(lr=lr, max_epochs=100, rng=np.random.default_rng(0), init_std=0.0).fit(X, y)
        runs[lr] = q
        print(f"η = {lr}: w = {q.w}, b = {q.b:.4f}, épocas = {q.epochs_run}, "
              f"acc = {q.accuracy(X, y):.4f}")
    a, b_ = runs[0.01], runs[1.0]
    ratio = 1.0 / 0.01
    print(f"w(η=1)/w(η=0.01) = {b_.w / a.w}  (esperado {ratio})")
    print(f"b(η=1)/b(η=0.01) = {b_.b / a.b:.4f}  (esperado {ratio})")
    print(f"mesmas previsões: {np.array_equal(a.predict(X), b_.predict(X))}; "
          f"mesmas épocas: {a.epochs_run == b_.epochs_run}")


if __name__ == "__main__":
    main()
    1. Semente fixa, criada uma vez: primeiro sorteia os dados e depois a inicialização de \(\mathbf{w}\), sempre na mesma ordem. Sem isso, os números da tabela final mudariam a cada execução.
    2. p.predict(X) != y é uma máscara booleana: True onde o perceptron erra. É ela que seleciona os pontos a marcar com "×" laranja.
    3. plt.close(fig) libera a figura da memória depois de salva.

    C — Treino e medição

    Com \(\eta = 0.01\), o treino convergiu na época 26 (a 26ª passada não teve nenhuma atualização; as 25 primeiras tiveram entre 1 e 4). No total foram apenas 73 atualizações. Resultados finais:

    • \(\mathbf{w} = (0{,}0505,\ 0{,}0289)\) e \(b = -0{,}25\);
    • acurácia final: 100% (0 erros nos 2000 pontos).

    D — Análise

    D.1 — Por que dados separáveis convergem rápido. A regra só altera os pesos quando há erro, e cada correção aproxima a fronteira de classificar aquele ponto corretamente. Se existe um hiperplano que separa as classes com folga, o teorema de convergência garante que o número total de atualizações é finito, limitado por \((R/\gamma)^2\), em que \(R\) é o maior \(\lVert (\mathbf{x}, 1) \rVert\) e \(\gamma\) é a margem da separação (com \(\lVert (\mathbf{w}^*, b^*) \rVert = 1\)). Como o número de atualizações é finito, alguma época não tem nenhuma — e é isso que o critério de parada detecta. Aqui: 73 atualizações no total, no máximo 4 por época (das 2000 previsões de cada época), e a época 26 sem nenhuma.

    Vale notar que "rápido" não significa "suave": a Figura 3 mostra uma acurácia que não é monótona, chegando a cair de 94% para 67% entre épocas. Isso acontece porque uma única correção é grande em relação aos pesos: uma atualização em \(\mathbf{x}_i\) soma \(\eta\,e\,(\mathbf{x}_i^\top \mathbf{x} + 1)\) ao score \(z\) de cada ponto \(\mathbf{x}\), e com \(\eta = 0.01\) e pontos a distâncias de 2 a 7 da origem isso é comparável ao valor de \(z\) que os pesos ainda pequenos produzem. A fronteira "balança" até encontrar uma posição entre as duas nuvens; quando encontra, não há mais erro para corrigir e tudo para.

    D.2 — Repetindo com \(\eta = 1.0\) (mesma semente, mesmos dados, mesma inicialização):

    \(\eta = 0.01\) \(\eta = 1.0\)
    Épocas até convergir 26 37
    Atualizações totais 73 101
    Acurácia final 100% 100%
    \(\mathbf{w}\) final \((0{,}0505,\ 0{,}0289)\) \((5{,}871,\ 3{,}359)\)
    \(b\) final \(-0{,}25\) \(-31{,}0\)
    \(\mathbf{w}/\lVert \mathbf{w} \rVert\) \((0{,}8681,\ 0{,}4963)\) \((0{,}8679,\ 0{,}4967)\)

    As direções normalizadas praticamente coincidem: o cosseno entre elas é \(\approx 0{,}9999999\) (ângulo de \(0{,}02^\circ\)). As retas ficam quase sobrepostas, com um pequeno deslocamento paralelo (distância à origem \(\lvert b \rvert / \lVert \mathbf{w} \rVert\) = 4,30 contra 4,58; ver Figura 2). Ambas separam os dados perfeitamente.

    O que \(\eta\) controla, então? Não a direção da fronteira, mas o tamanho de cada passo relativo ao tamanho dos pesos iniciais. Com inicialização em torno de \(0{,}01\), um passo de \(\eta = 1.0\) move \(\mathbf{w}\) em cerca de \(\eta \lVert \mathbf{x} \rVert \approx 2\) a \(7\), isto é, centenas de vezes o valor inicial: depois da primeira atualização a inicialização é esquecida e o treino se comporta como uma partida em zero. Com \(\eta = 0.01\), o passo (cerca de \(0{,}02\) a \(0{,}07\)) é da ordem dos pesos iniciais, então a inicialização ainda influencia o caminho. Por isso o número de épocas difere (26 contra 37) sem que a fronteira mude de direção. O item seguinte mostra exatamente isso.

    D.3 — \(\eta\) só reescala (partindo de \(\mathbf{w} = 0\), \(b = 0\)).

    Afirmação: sejam duas execuções com \(\eta_1\) e \(\eta_2\), mesmos dados, mesma ordem e partida em zero. Então, em todo instante \(t\) (após cada amostra),

    \[ \mathbf{w}^{(2)}_t = \frac{\eta_2}{\eta_1}\,\mathbf{w}^{(1)}_t, \qquad b^{(2)}_t = \frac{\eta_2}{\eta_1}\,b^{(1)}_t. \]

    Prova por indução em \(t\). Base: em \(t = 0\) ambos são zero, e \(0 = (\eta_2/\eta_1)\cdot 0\). Passo: suponha a relação válida em \(t\). O escore da execução 2 é \(z^{(2)} = \mathbf{w}^{(2)\top}_t \mathbf{x} + b^{(2)}_t = (\eta_2/\eta_1)\,z^{(1)}\). Como \(\eta_2/\eta_1 > 0\), \(z^{(2)}\) e \(z^{(1)}\) têm o mesmo sinal (e são zero juntos), logo \(\text{step}(z^{(2)}) = \text{step}(z^{(1)})\) e o erro \(e = y - \hat{y}\) é o mesmo nas duas execuções. Então

    \[ \mathbf{w}^{(2)}_{t+1} = \mathbf{w}^{(2)}_t + \eta_2\, e\, \mathbf{x} = \frac{\eta_2}{\eta_1}\left(\mathbf{w}^{(1)}_t + \eta_1\, e\, \mathbf{x}\right) = \frac{\eta_2}{\eta_1}\,\mathbf{w}^{(1)}_{t+1}, \]

    e o mesmo cálculo vale para \(b\). \(\blacksquare\)

    Consequências. (i) A fronteira \(\mathbf{w}^\top \mathbf{x} + b = 0\) é o mesmo conjunto de pontos nas duas execuções (multiplicar a equação por uma constante positiva não a altera). (ii) Como as previsões são idênticas a cada passo, os erros são os mesmos em todas as épocas: o número de épocas até convergir e a acurácia por época são idênticos. Em zero, \(\eta\) é só uma escolha de unidade.

    Verificação numérica (script, com init_std=0): \(\eta = 0.01\) dá \(\mathbf{w} = (0{,}05868,\ 0{,}03350)\), \(b = -0{,}31\); \(\eta = 1.0\) dá \(\mathbf{w} = (5{,}86808,\ 3{,}35029)\), \(b = -31{,}0\). A razão é exatamente \(100\) em todas as componentes, e ambas convergem em 37 épocas. Isso também explica os 37 épocas do \(\eta = 1.0\) de D.2: nesse caso a inicialização é irrelevante e a execução equivale à partida em zero. Com inicialização não nula a relação vale só de forma aproximada: rodar com \(\eta\) equivale a rodar com \(\eta = 1\) partindo de \(\mathbf{w}_0/\eta\), e é por isso que \(\eta = 0.01\) (que enxerga \(\mathbf{w}_0/\eta\) de ordem 1) difere.

from pathlib import Path
from math import erf, sqrt

import matplotlib.pyplot as plt
import numpy as np

from perceptron import (
    LIGHT_BLUE,
    NAVY,
    ORANGE,
    PINK,
    Perceptron,
    decision_line,
    generate_two_classes,
)

FIGURES = Path(__file__).resolve().parents[1] / "figures"
RNG = np.random.default_rng(42)  # (1)!

MEAN0, MEAN1, VAR, N_PER_CLASS = [3.0, 3.0], [4.0, 4.0], 1.5, 1000
COLORS = {0: NAVY, 1: PINK}  # paleta: só tons de rosa, azul e laranja


def scatter_classes(ax, X, y):
    for cls in (0, 1):
        m = y == cls
        ax.scatter(X[m, 0], X[m, 1], s=10, alpha=0.4, color=COLORS[cls], label=f"Classe {cls}")
    ax.set_xlabel("$x_1$")
    ax.set_ylabel("$x_2$")


def plot_figure4(X, y):
    fig, ax = plt.subplots(figsize=(7, 6))
    scatter_classes(ax, X, y)
    ax.set_title("Figura 4 — Dados sobrepostos: 1000 pontos por classe")
    ax.legend()
    return fig


def plot_figure5(X, y, p):
    """Dois painéis: pesos finais (esq.) e pesos do bolso (dir.), cada um com a sua
    fronteira e os seus erros marcados com X vermelho. Eixos compartilhados."""
    fig, axes = plt.subplots(1, 2, figsize=(13, 6), sharex=True, sharey=True)
    x1 = np.array([X[:, 0].min() - 0.5, X[:, 0].max() + 0.5])
    cases = [
        ("Pesos finais", p.w, p.b, ORANGE),
        ("Pesos do bolso (pocket)", p.pocket_w, p.pocket_b, LIGHT_BLUE),
    ]
    for ax, (name, w, b, color) in zip(axes, cases):
        scatter_classes(ax, X, y)
        wrong = p.predict(X, w, b) != y
        ax.scatter(X[wrong, 0], X[wrong, 1], marker="x", s=25, color=ORANGE, alpha=0.85,
                   label=f"Erros ({wrong.sum()})")
        ax.plot(x1, decision_line(w, b, x1), color=color, lw=2.5, label="Fronteira")
        ax.set_ylim(X[:, 1].min() - 0.5, X[:, 1].max() + 0.5)
        ax.set_title(f"{name} — acurácia {1 - wrong.mean():.2%}")
        ax.legend(loc="upper right")
    fig.suptitle("Figura 5 — Fronteiras de decisão em dados sobrepostos")
    return fig


def plot_figure6(p):
    epochs = np.arange(1, len(p.acc_history) + 1)
    fig, ax = plt.subplots(figsize=(8, 4.5))
    ax.plot(epochs, p.acc_history, color=LIGHT_BLUE, lw=1.2, label="Acurácia atual (fim da época)")
    ax.plot(epochs, p.best_acc_history, color=ORANGE, lw=2.2, label="Melhor até agora (bolso)")
    ax.axhline(0.5, color=NAVY, ls=":", label="Chute (50%)")
    ax.set_xlabel("Época")
    ax.set_ylabel("Acurácia no conjunto completo")
    ax.set_title("Figura 6 — Acurácia atual vs. melhor acurácia (bolso)")
    ax.legend(loc="center right")
    return fig


def normal_cdf(z):
    return 0.5 * (1 + erf(z / sqrt(2)))


def main() -> None:

    D.1 — Por que 50,05% e 72,85%. A melhor reta possível para estes dados é a mediatriz das médias, \(x_1 + x_2 = 7\). Como as distribuições são gaussianas com mesma covariância, a acurácia ótima teórica é \(\Phi\!\left(\tfrac{d}{2\sigma}\right)\) com \(d = \sqrt{2}\) e \(\sigma = \sqrt{1{,}5}\), ou seja \(\approx 71{,}8\%\); essa reta acerta 72,60% desta amostra. Os 72,85% do bolso estão, portanto, no teto do que uma reta pode fazer (ligeiramente acima por selecionarmos o melhor ponto do treino na própria amostra, o que é otimista). Já os pesos finais, com 50,05%, não passam de um chute: a Figura 5 (esquerda) mostra a fronteira num canto do plano, fora da nuvem, com todos os pontos do mesmo lado. Eles prevêem a classe 1 para os 2000 pontos (acertam os 1000 da classe 1 e apenas 1 da classe 0).

    Por que o treino deixa a fronteira ali. Uma atualização em \(\mathbf{x}_i\) com erro \(e\) soma \(\eta\,e\,(\mathbf{x}_i^\top \mathbf{x} + 1)\) ao escore de cada ponto \(\mathbf{x}\). O "\(+1\)" é a contribuição do viés; o resto, \(\mathbf{x}_i^\top \mathbf{x}\), vem de \(\mathbf{w}\). Aqui \(\lVert \mathbf{x} \rVert \approx 5{,}07\) (média medida) e a nuvem está toda no primeiro quadrante, longe da origem e com pouca dispersão angular; portanto \(\mathbf{x}_i^\top \mathbf{x} \approx \lVert \boldsymbol{\mu} \rVert^2 \approx 24\) para quase qualquer par de pontos (a média medida dá \(\approx 24\)). Cada erro muda o escore de todos os pontos por quase o mesmo valor, cerca de \(\pm 0{,}26\), e só 1 dessas 26 unidades vem do viés: em cada passo \(\mathbf{w}\) se move cerca de \(\lVert \mathbf{x} \rVert \approx 5\) vezes mais que \(b\) (0,05 contra 0,01). A consequência é que a fronteira fica presa perto da origem — a distância dela à origem, \(\lvert b \rvert / \lVert \mathbf{w} \rVert\), é 0,65 no fim do treino, enquanto o centro da nuvem está a 4,95. Para atravessar a nuvem, \(b\) teria de chegar perto de \(-\mathbf{w}^\top \boldsymbol{\mu} \approx -0{,}30\); mas \(b\) só anda \(\pm 0{,}01\) por erro, e como as classes se sobrepõem os erros de sinais opostos se alternam e se cancelam (\(\lvert b \rvert \le 0{,}04\) ao fim de toda época).

    Com esse deslocamento em bloco, cada erro joga os 2000 pontos de um lado para o outro da fronteira: só 3,82 atualizações por época em média (entre 2 e 4), mas cada uma vira quase toda a previsão. Como a ordem é fixa e o fim de toda época é um trecho só de classe 1 (as últimas 1000 amostras), o estado em que cada época termina é quase sempre o "prevê tudo como classe 1" (em todas as 100 épocas, pelo menos 97,6% dos pontos são previstos como classe 1), que rende ≈ 50%. A Figura 6 confirma: a curva azul-clara fica entre 50,0% e 52,4% em todas as épocas. O bolso, por sua vez, só precisa que em algum instante os pesos tenham passado por uma boa reta: isso ocorreu na atualização 53, com \(\mathbf{w} \approx (0{,}0068,\ 0{,}0066)\) e \(b = -0{,}05\), ou seja a reta \(x_1 + x_2 \approx 7{,}4\), quase a mediatriz.

    D.2 — Figura 3 versus Figura 6; o teorema. Na Figura 3 a acurácia oscila no começo e depois sobe até 100% e fica ali: há uma época sem atualização e o treino para. Na Figura 6 a curva azul-clara nunca estabiliza (fica em torno de 50%) e o bolso é uma escada não decrescente que satura em 72,85%. O teorema de convergência do perceptron (NOVIKOFF, 1962) diz: se existe \((\mathbf{w}^*, b^*)\) e \(\gamma > 0\) com \(y_i(\mathbf{w}^{*\top}\mathbf{x}_i + b^*) \ge \gamma\) para todo \(i\) (separabilidade linear com margem positiva) e \(\lVert (\mathbf{x}_i, 1) \rVert \le R\) (com \(\lVert (\mathbf{w}^*, b^*) \rVert = 1\)), então o algoritmo comete um número finito de erros, no máximo \((R/\gamma)^2\) quando parte de zero, e termina com zero erro, para qualquer \(\eta > 0\). A hipótese violada aqui é a separabilidade linear: as classes se sobrepõem, e nenhuma reta acerta todos os pontos (a melhor reta erra ≈ 28%). Consequência direta: uma época sem atualização exigiria pesos que acertassem os 2000 pontos, o que é impossível; então o critério de parada nunca dispara e as atualizações nunca se esgotam.

    D.3 — Mais épocas ou \(\eta\) menor resolvem? Não, e dá para ver pela regra de atualização.

    • Mais épocas. O teorema não vale, e não há razão para o número de atualizações se esgotar: a cada passada, os erros continuam a chegar. Os pesos finais continuam a ser uma sequência que oscila (D.1), não uma sequência que converge. Mais épocas apenas dão mais chances ao bolso, cujo teto é a melhor reta possível (≈ 73%).
    • \(\eta\) menor. Pela prova do D.3 do Exercise 1, a partida em zero com qualquer \(\eta\) produz a mesma sequência de erros, só em outra escala. O que faz a fronteira escapar da nuvem é a geometria (\(\mathbf{x}_i^\top \mathbf{x} \approx 25 \gg 1\), então \(\mathbf{w}\) domina \(b\)), e ela não depende de \(\eta\). Diminuir \(\eta\) só muda a escala dos pesos. Com a inicialização \(\mathcal{N}(0, 0.01)\) a equivalência é aproximada (diminuir \(\eta\) aumenta o peso relativo de \(\mathbf{w}_0\)), mas \(\mathbf{w}_0\) é sorteado sem informação sobre as classes e não ajuda: a tabela abaixo confirma.

    Com 10 vezes mais épocas o bolso ganha 0,5 ponto percentual (10 pontos em 2000), o que é compatível com sorte na seleção do melhor ponto, não com melhora do modelo; e os pesos finais ficam em 50% em todas as configurações. Ferramentas que ataquem a causa (por exemplo, centralizar os dados ou trocar a perda) estão fora do escopo do exercício e não foram testadas.
